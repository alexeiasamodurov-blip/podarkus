# Podarkus

Сайт для подбора подарков по анкете: 1 537 идей, возраст, бюджет, повод, интересы и ограничения.

Каталог обновлён 29 октября 2026: к исходным 500 добавлено 1 037 идей в 22 категориях. У 63 новых идей сохранены источники направлений TikTok/Pinterest и тематических обзоров в `catalog-sources.json`. Это редакционное вдохновение, а не рейтинг продаж или подтверждение наличия в России. Все диапазоны цен ориентировочные. Конкретные увлечения и названия коллекций распознаются словарём; возраст, бюджет и исключения применяются и к обычному подбору, и к кандидатам для ИИ.

Все изображения, шрифты, стили и каталог встроены в index.html. Обычный подбор работает в браузере без отправки ответов на сервер. По отдельной кнопке пользователь может отправить анкету и уточнение интересов в Cloudflare Workers AI. Для этого нужен вход в Podarkus. Если ИИ недоступен, обычные результаты остаются доступны.

Регистрация и вход работают через Firebase Authentication: email, пароль, подтверждение адреса и восстановление пароля. Вход сохраняется только на время вкладки через browserSessionPersistence. Пароли не сохраняются приложением. История подбора и избранное к аккаунту не привязаны.

Проект Firebase: podarkus-1b631, тариф Spark. Способ входа: Email/Password. Домен сайта: alexeiasamodurov-blip.github.io. Серверная политика паролей должна требовать минимум 10 символов. Письма отправляет Firebase; применяются квоты бесплатного тарифа.

auth-config.json содержит только публичные настройки веб-приложения Firebase. Это не административный ключ и не даёт доступа к списку аккаунтов. Не добавляйте в репозиторий service-account JSON, Admin SDK credentials или выгрузки пользователей.

Код форм: src/auth-ui.js. Подключение Firebase SDK: src/auth.js. Разметка формы: src/auth-dialog.html; при её изменении обновите соответствующий диалог в index.html. Собранный браузерный файл: assets/auth.js.

Разработка: npm ci, npm test, npm run build. После изменения JS пересоберите assets/auth.js и увеличьте параметр v у ссылки на него в index.html. Сборка останавливается, если конфигурация проекта не заполнена.

Публикация: GitHub Pages, ветка main, корневая папка. Файл .nojekyll отключает обработку Jekyll.

При обновлении отправьте index.html, assets/auth.js и assets/ai.js вместе с изменёнными исходниками в main. База аккаунтов хранится только в Firebase. Старая автономная версия для флешки хранится отдельно и аккаунты не поддерживает.

## ИИ Cloudflare

Endpoint: https://podarkus-ai.podarkus.workers.dev. Модель: @cf/qwen/qwen3-30b-a3b-fp8. Работает на бесплатном плане Workers AI с общей дневной квотой; при её исчерпании возвращается понятная ошибка и остаётся обычный подбор. Платный тариф не требуется и не включается кодом.

Worker проверяет подпись Firebase ID token, issuer, audience и время действия. CORS разрешён только для origin сайта. Ограничитель — 3 запроса за 60 секунд на UID, локально на узле Cloudflare, а не строгая глобальная квота. Лимит тела 16 KB. Произвольные цены, ссылки и идентификаторы от модели отбрасываются: карточки собираются из каталога, прошедшего фильтры возраста, бюджета и известных запретов. Свободный текст и аллергии требуют самостоятельной проверки состава товара; ИИ не проверяет магазины, доставку или наличие.

Текст анкеты отправляется только после явного нажатия кнопки с уведомлением. Имя и email в промпт не включаются. Firebase ID token используется только для проверки доступа, модель его не получает. Логи промптов в Worker не включены. Пользователю предлагается не вводить личные данные. Новые запреты и бюджет следует менять в анкете, уточнение предназначено для интересов.

Исходники: src/ai-ui.js, src/ai.js, worker/service.js, worker/index.js. Публичный адрес задан в ai-config.json; секретов Cloudflare в браузере нет. Авторизация Wrangler хранится вне репозитория в зашифрованном файле с ключом в Windows Credential Manager.

После изменения каталога: `node scripts/extract-ai-catalog.mjs`, `npm test`, затем `npx wrangler deploy --config worker/wrangler.jsonc`, `npm run build` и публикация GitHub Pages. Worker загружается отдельно; файлы worker в репозитории сами по себе не запускаются на GitHub Pages. Проверка `/health` подтверждает доступность Worker, а реальный авторизованный `/recommend` — работу модели.
